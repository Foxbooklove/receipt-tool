## 한 줄 요약

연구비 정산 때 영수증을 하나씩 보며 엑셀에 수기 입력하던 작업을, 스크린샷을 한 번에 올려 자동으로 표로 만드는 웹 도구로 바꿨다. 파싱은 연구실 PC의 로컬 AI 모델이 수행해 결제 정보가 외부로 나가지 않는다.

## 먼저 읽을 것

발표를 준비한다면 [시연-시나리오.md](시연-시나리오.md)의 **녹화 전 준비** 항목부터 본다.
모델을 미리 메모리에 올려두지 않으면 영상 첫 장에서 40초 동안 화면이 멈춘다. 재촬영 사유가 된다.

숫자를 인용할 때는 [측정값.md](측정값.md)에 있는 값만 쓴다. 거기 없는 수치는 아직 측정하지 않은 것이다.

## 무엇을 해결했나

연구실에서 실험 부품을 쿠팡으로 사면 정산 때 결제 내역을 하나씩 열어보며 엑셀에 옮겨 적어야 한다. 일자, 사용처, 금액, 분류를 손으로 친다. 영수증이 수십 장이면 수십 번 반복한다.

이 도구는 스크린샷을 통째로 올리면 그 항목들을 뽑아 표로 만들어준다. 사람은 틀린 칸만 고치고 엑셀로 내려받는다.

## 어떻게 동작하나

```
영수증 스크린샷 여러 장 업로드
  → 브라우저가 로컬 AI 모델(Qwen2.5-VL)에 한 장씩 전송
  → 모델이 일자·사용처·금액·분류를 JSON으로 추출
  → 화면의 표에 채워짐 (사람이 검토·수정)
  → 엑셀 다운로드 + Supabase 저장
```

## 이 프로젝트에서 강조할 점

**1. 파싱이 로컬에서 일어난다.** 영수증에는 카드번호 일부와 결제 정보가 들어 있다. 외부 AI API로 보내지 않고 연구실 PC의 GPU에서 처리한다. 화면 상단 배지와 하단 문구로 이 점을 명시했다.

**2. 자동 확정하지 않는다.** AI가 뽑은 결과를 그대로 쓰지 않고 반드시 사람이 검토하는 단계를 거친다. 실제로 상품명에는 오독이 남아 있고, 시연에서 그것을 고치는 장면을 보여준다. 완벽한 척하지 않는 편이 설계 의도를 더 잘 드러낸다.

**3. 금액 계산의 함정을 처리했다.** 쿠팡 거래명세표는 배송비가 별도 행이라 `총 거래액 합계`와 `실제 총 결제 금액`이 다르다. 예를 들어 5,400원짜리 부품에 배송비 2,900원이 붙으면 실제 결제액은 8,300원이다. 프롬프트에서 이 부분을 명시적으로 지시해 마지막 행을 읽게 했다. 단순히 "금액을 읽어라"라고 했다면 전부 틀렸을 것이다.

**4. 두 종류의 증빙 서식을 모두 처리한다.** 쿠팡은 `거래명세표`(표 형식)와 `신용카드 매출전표`(목록 형식) 두 가지를 발급하는데, 항목 위치도 이름도 다르다. 모델이 이미지를 보고 스스로 판단해 알맞은 규칙을 적용한다.
