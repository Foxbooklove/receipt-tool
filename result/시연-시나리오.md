# 시연 영상 시나리오

전체 5~6분 분량. 순서대로 찍으면 7단계가 모두 화면에 담긴다.

---

## 녹화 전 준비 (중요)

이 순서를 지키지 않으면 녹화 도중 파싱이 실패한다.

**1. Ollama를 CORS 허용 상태로 띄운다**

```powershell
OLLAMA_ORIGINS='*' ollama serve
```

이미 Ollama가 떠 있다면 먼저 종료해야 한다. `setx`로 환경변수를 넣어둔 것만으로는 이미 실행 중인 프로세스에 반영되지 않는다.

**2. 모델을 미리 메모리에 올린다**

```powershell
ollama run qwen2.5vl:7b "테스트"
```

이걸 안 하면 **영상 속 첫 장에서 40초 동안 멈춘다.** 모델을 처음 불러올 때만 생기는 지연이다. 반드시 미리 한 번 돌려둔다.

**3. 터널을 연다** (배포본에서 시연하는 경우에만)

```powershell
cloudflared tunnel --url http://localhost:11434 --http-host-header localhost:11434
```

`--http-host-header`를 빠뜨리면 모든 요청이 403으로 막힌다. 출력되는 `https://....trycloudflare.com` 주소를 복사해둔다.

**4. 브라우저 준비**

- 앱 화면의 `파싱 서버 설정`에 위 터널 주소를 붙여넣고 한 번 테스트해본다
- 탭을 미리 정리한다: 앱 / Supabase / GA / Search Console
- 알림, 메신저를 꺼둔다

**5. 영수증 준비**

영상용으로는 **4~5장**이 적당하다. 15장은 화면에서 기다리는 시간이 길다. **카드 매출전표를 한 장 섞는다** — 두 서식을 모두 처리한다는 걸 보여주기 위해서다.

---

## 1. 문제 제기 (30초)

쿠팡 거래명세표 스크린샷을 화면에 띄우고, 빈 엑셀 창을 나란히 놓는다.

> "연구비 정산을 하려면 이런 결제 내역을 하나씩 열어서 날짜, 금액, 물품명을 엑셀에 옮겨 적어야 합니다. 영수증이 수십 장이면 이걸 수십 번 반복합니다."

엑셀에 한 줄을 직접 타이핑해 보이면 지루함이 전달된다.

---

## 2. 서비스 소개 (30초) — 1·3단계

배포 주소 `receipt-tool-rho.vercel.app` 접속.

> "이 작업을 자동화한 도구입니다. 웹에 배포되어 있고, 설치할 것은 없습니다."

상단 배지를 가리키며:

> "영수증에는 결제 정보가 들어 있습니다. 그래서 외부 AI 서비스를 쓰지 않고, 연구실 PC에서 직접 AI 모델을 돌립니다."

---

## 3. 핵심 시연 (90초) — 2단계

영수증 4~5장을 **드래그앤드롭**으로 올린다.

> "여러 장을 한 번에 올립니다."

진행률 바가 차오르는 동안:

> "한 장씩 순서대로 처리합니다. GPU 메모리가 12GB라 동시에 여러 장을 돌리면 오히려 느려지기 때문에 의도적으로 순차 처리합니다."

표가 채워지면 **요약 카드**를 가리킨다.

> "4장을 12.5초에, 장당 3초 정도에 처리했습니다."

**여기서 반드시 보여줄 것 — 배송비 처리**

배송비가 붙은 행(8,300원)을 원본과 나란히 놓고:

> "이 부분이 까다로웠습니다. 쿠팡 거래명세표는 물건값과 배송비가 다른 줄에 있어서, 표의 '총 거래액 합계'는 5,400원인데 실제 결제한 금액은 배송비를 더한 8,300원입니다. 그냥 '금액을 읽어라'라고 시키면 전부 틀립니다. 맨 아래 '실제 총 결제 금액' 줄을 읽도록 명시적으로 지시했습니다."

**카드 매출전표 행을 가리키며**

> "쿠팡은 두 종류의 증빙을 발급하는데 서식이 완전히 다릅니다. 이건 카드 매출전표라 판매자 이름과 카드 종류가 나옵니다. AI가 이미지를 보고 어떤 서식인지 스스로 판단합니다."

---

## 4. 검토 단계 (40초) — 설계 의도

상품명에 오독이 있는 칸을 찾아 클릭하고 직접 고친다.

> "AI가 완벽하지는 않습니다. 상품명에서 '탐사'를 '타사'로 읽는 식의 오류가 있습니다. 그래서 결과를 자동으로 확정하지 않고, 사람이 검토하는 단계를 반드시 거치도록 만들었습니다."

> "다만 정산에서 중요한 건 날짜와 금액인데, 이 숫자들은 검증한 범위에서 전부 정확했습니다. 오류는 참고용인 비고 칸에만 나타납니다."

썸네일을 클릭해 원본을 띄운다.

> "각 줄마다 원본 영수증을 바로 확인할 수 있어서 검토가 빠릅니다."

---

## 5. 결과물 (30초)

`엑셀 다운로드` 클릭 → 파일을 연다.

> "정산 양식 그대로 엑셀이 나옵니다. 컬럼 이름은 연구실 양식에 맞춰 한 곳만 고치면 바뀝니다."

`Supabase에 저장` 클릭 → 성공 메시지.

---

## 6. DB 확인 (30초) — 5단계

Supabase 대시보드 → Table Editor → `receipts`

> "저장한 데이터입니다. 영수증 원본 이미지는 Storage에 따로 보관됩니다."

Storage 버킷의 이미지 목록도 보여준다.

---

## 7. 측정 (40초) — 6단계

GA `보고서 → 실시간` 화면.

> "Google Analytics로 방문자를 측정합니다."

Supabase `parse_metrics` 테이블.

> "그런데 GA로는 '영수증 한 장을 처리하는 데 몇 초 걸렸는지'를 알 수 없습니다. 그래서 처리 건수와 소요 시간을 따로 기록합니다. 이 값이 아까 화면에 보였던 요약 카드입니다. 측정한 값을 사용자에게 바로 돌려주는 구조입니다."

---

## 8. 검색 등록 (20초) — 7단계

Search Console → "소유권이 자동으로 확인됨" 화면 → 사이트맵 제출 목록.

> "Search Console에 등록했습니다. 애널리틱스로 소유권이 자동 확인됐고, 사이트맵과 색인 생성을 요청했습니다. 실제 검색 노출까지는 며칠 걸립니다."

---

## 9. 마무리 (20초)

> "수기로 하던 정산 입력을 자동화했고, 영수증 이미지가 외부로 나가지 않도록 AI를 직접 돌리는 구조로 만들었습니다."

---

## 촬영 팁

- **모델을 미리 올려두지 않으면 첫 장에서 40초 멈춘다.** 이것만 지켜도 재촬영을 피한다.
- 브라우저 확대를 110~125%로 두면 표 글씨가 영상에서 읽힌다.
- 진행률이 차오르는 구간은 실시간으로 두는 편이 낫다. 편집으로 잘라내면 "정말 도는지" 의심을 산다.
- 실패해도 당황하지 말 것. 검토 화면에서 고치는 게 원래 설계다.
